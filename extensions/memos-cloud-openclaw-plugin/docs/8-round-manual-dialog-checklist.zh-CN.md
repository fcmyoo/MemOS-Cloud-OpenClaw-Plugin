# MemOS Cloud OpenClaw Plugin 8 轮实际对话手工验证清单

> 目标：把插件在真实对话中的关键能力，整理成现场可逐项打勾的验收清单。
> 适用对象：产品验收、联调、演示、上线前冒烟。
> 范围：只验证 lifecycle 记忆召回 / 写回链路，不验证业务模型本身的回答质量。

## 使用前准备

### 环境前置检查

- [ ] 插件已启用：`plugins.entries.memos-cloud-openclaw-plugin.enabled = true`
- [ ] 已重启 OpenClaw gateway
- [ ] 已配置 `MEMOS_API_KEY` 或插件 `config.apiKey`
- [ ] 如需验证远端召回，MemOS Cloud 服务可访问
- [ ] 如需验证本地精排召回，已配置 LanceDB 相关参数和可用 embedding key
- [ ] 当前测试使用固定用户，避免和其他真实会话混淆
- [ ] 已准备可查看日志的终端，便于观察 `recall.success` / `add.success` / `add.failed` / `recall.failed`

### 建议测试配置

建议先使用一组容易观察的配置：

```json
{
  "plugins": {
    "entries": {
      "memos-cloud-openclaw-plugin": {
        "enabled": true,
        "config": {
          "apiKey": "YOUR_API_KEY",
          "userId": "manual-checklist-user",
          "recallEnabled": true,
          "addEnabled": true,
          "captureStrategy": "last_turn",
          "includeAssistant": true,
          "memoryGrayPercent": 100,
          "memoryDegradeOnError": true,
          "recallGlobal": true,
          "memosSearchFallbackEnabled": true,
          "memosSearchFallbackMode": "weak-or-empty"
        }
      }
    }
  }
}
```

## 第 1 轮：基础写回是否生效

### 用户输入

```text
请记住：我喜欢你先给结论，再给依据。
```

### 验证点

- [ ] 本轮结束后插件触发 `agent_end`
- [ ] 仅最后一轮 user / assistant 被写入 MemOS（默认 `captureStrategy = last_turn`）
- [ ] 日志里能看到 `add.success`
- [ ] 没有出现缺少 API Key 的告警

### 预期观察

- 助手正常回复，不因插件报错中断
- 日志出现 `event = "add.success"`
- `message_count` 通常为 2（user + assistant）
- `scope_key` / `session_id` 有值

### 通过标准

- [ ] 本轮对话正常完成
- [ ] 日志明确出现一次 `add.success`
- [ ] 无阻断型异常

### 失败标准

- [ ] 对话直接报错或中断
- [ ] 未看到 `add.success`
- [ ] 出现 `Missing MEMOS_API_KEY`、HTTP 401、网络错误且未降级

---

## 第 2 轮：远端记忆召回是否命中上一轮偏好

### 用户输入

```text
我刚才对你的回复风格有什么要求？
```

### 验证点

- [ ] 插件在 `before_agent_start` 触发召回
- [ ] 远端 MemOS 检索命中第 1 轮写入的偏好
- [ ] 日志出现 `recall.success`
- [ ] 注入上下文后，助手回答能明确提到“先给结论，再给依据”

### 预期观察

- 回答内容应体现对上一轮偏好的回忆，而不是泛泛猜测
- 若为纯 MemOS 召回链路，日志中应有 MemOS recall 成功信息
- 召回内容应偏向用户真实输入，不应凭空杜撰新的偏好

### 通过标准

- [ ] 助手明确复述或等价表达出该偏好
- [ ] 日志出现 `recall.success`
- [ ] 本轮结束后再次出现 `add.success`

### 失败标准

- [ ] 助手无法说出上一轮偏好
- [ ] 日志没有召回成功记录
- [ ] 回答与真实输入明显不符

---

## 第 3 轮：连续多条偏好写回后，后续可继续召回

### 用户输入

```text
再记住一条：我默认用中文简体交流。
```

### 验证点

- [ ] 新的一轮偏好再次写回成功
- [ ] 不影响已有记忆的存储
- [ ] 日志再次出现 `add.success`

### 预期观察

- 助手正常确认或复述该偏好
- 写回成功且不影响会话继续进行

### 通过标准

- [ ] 本轮结束后出现 `add.success`
- [ ] 无异常中断

### 失败标准

- [ ] 无写回日志
- [ ] 写回报错导致对话异常

---

## 第 4 轮：多条用户偏好可同时被召回

### 用户输入

```text
总结一下你现在记得我的两个沟通偏好。
```

### 验证点

- [ ] 能同时召回第 1 轮和第 3 轮中的偏好
- [ ] 回答中至少包含“先给结论，再给依据”与“默认用中文简体”两点
- [ ] 若日志可见 unified recall / memos summary，可看到非空召回结果

### 预期观察

- 助手输出两条稳定偏好，且与前文一致
- 不应只命中一条，也不应夹带无关偏好

### 通过标准

- [ ] 两条偏好都被明确提及
- [ ] 日志出现 `recall.success`
- [ ] 回答与前文一致，无明显幻觉

### 失败标准

- [ ] 只召回一条或两条都没召回
- [ ] 输出混入用户未说过的偏好
- [ ] 召回日志为空或失败

---

## 第 5 轮：跨轮事实信息写回与召回

### 用户输入

```text
请记住一个事实：我现在主要在做 OpenClaw 相关项目。
```

### 验证点

- [ ] 普通事实信息也能被写回，不只限于偏好
- [ ] 本轮结束后出现 `add.success`
- [ ] 后续轮次可用于事实型召回

### 预期观察

- 助手正常确认该事实
- 日志显示写回成功

### 通过标准

- [ ] 出现 `add.success`
- [ ] 本轮对话正常结束

### 失败标准

- [ ] 写回失败
- [ ] 事实类信息无法进入记忆链路

---

## 第 6 轮：事实与偏好混合召回是否稳定

### 用户输入

```text
你现在记得我的项目背景和回复偏好吗？请一起说出来。
```

### 验证点

- [ ] 能同时回忆事实类信息和偏好类信息
- [ ] 至少应包含：OpenClaw 项目、先给结论再给依据、默认中文简体
- [ ] 若启用统一召回，回答应体现多来源记忆融合后的结果

### 预期观察

- 助手把“项目背景”和“沟通偏好”分开说更容易判定
- 日志出现 `recall.success`
- 若本地 LanceDB 和远端 MemOS 同时启用，日志中可能包含本地 / 远端融合信息

### 通过标准

- [ ] 至少正确说出 1 条事实 + 2 条偏好
- [ ] 无明显记忆串台
- [ ] 日志有 `recall.success`

### 失败标准

- [ ] 只说出模糊印象，没有具体内容
- [ ] 把事实和偏好说错或混淆
- [ ] 召回失败

---

## 第 7 轮：弱本地命中 / 回退远端召回是否符合预期

> 本轮建议在启用 LanceDB 的环境下执行；若未启用 LanceDB，可标记为“不适用”。

### 用户输入

```text
结合你记得的信息，描述一下我目前的工作上下文。
```

### 验证点

- [ ] 当本地召回结果为空或分数较弱时，插件会回退到 MemOS 搜索
- [ ] 日志中能看到 fallback 生效迹象
- [ ] 最终回答仍能提到之前写入的关键事实上下文

### 预期观察

- 若本地结果强，可能只走本地精排，不一定触发远端
- 若本地结果弱或为空，日志中应能看到 fallback 相关字段，例如：
  - `fallback.enabled = true`
  - `fallback.should_fallback = true`
  - `fallback.reason` 为弱命中或空结果相关原因
- 回答仍应包含 OpenClaw 项目、中文简体、结论优先等已知信息中的若干项

### 通过标准

- [ ] 在弱命中/空命中条件下，远端补召回生效
- [ ] 最终回答仍可用且包含历史记忆
- [ ] 日志里可观察到 fallback 证据

### 失败标准

- [ ] 弱本地命中后未回退，导致回答丢失历史上下文
- [ ] fallback 配置打开但行为与预期不一致
- [ ] 日志没有任何可佐证字段

### 不适用判定

- [ ] 当前环境未启用 LanceDB，本轮跳过，不计入失败

---

## 第 8 轮：异常场景下是否优雅降级，不阻断主对话

> 本轮是容错验证。建议在测试环境执行，例如临时改错 API Key、断开 MemOS 服务、或使用不可达地址。

### 用户输入

```text
现在请继续回答：你还记得我刚才说过的偏好吗？
```

### 验证点

- [ ] 当 MemOS 检索或写回失败时，对话主流程不应被插件直接打断（前提：`memoryDegradeOnError = true`）
- [ ] 日志出现 `recall.failed` 或 `add.failed`
- [ ] 助手仍然能给出可用答复，哪怕记忆能力退化

### 预期观察

- 可能无法正确回忆全部历史内容，但系统应继续响应
- 日志中存在失败事件，并标注 `degrade` 状态
- 若只影响 recall，则回答质量下降但不崩溃
- 若只影响 add，则本轮结束后写回失败但用户侧仍能收到回答

### 通过标准

- [ ] 对话未被阻断
- [ ] 日志出现失败事件且系统继续工作
- [ ] 能确认降级生效，而不是直接抛出未处理异常

### 失败标准

- [ ] 插件异常直接导致主流程报错
- [ ] 用户收不到回答
- [ ] 无日志，无法判断失败原因

## 整体通过判定规则

### 单轮判定

- [ ] 每轮都以该轮“通过标准”为准进行独立判定
- [ ] 若某轮存在前置条件不满足（例如第 7 轮未启用 LanceDB），可标记“不适用”

### 总体通过

满足以下条件，可判定本次 8 轮验证通过：

- [ ] 第 1、2、4、6、8 轮全部通过
- [ ] 第 3、5 轮至少通过其写回验证
- [ ] 第 7 轮若适用则通过；若不适用则明确标注跳过原因
- [ ] 全流程没有出现“插件错误导致主对话不可用”的阻断性问题

### 总体失败

出现以下任一情况，判定本次验证失败：

- [ ] 基础写回（第 1 轮）失败
- [ ] 基础召回（第 2 轮）失败
- [ ] 多条偏好或事实混合召回（第 4 / 6 轮）明显失真
- [ ] 降级能力（第 8 轮）失效，导致主流程中断
