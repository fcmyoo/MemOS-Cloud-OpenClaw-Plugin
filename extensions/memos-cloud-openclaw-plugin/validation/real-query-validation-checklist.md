# MemOS Cloud Plugin 真实查询验证清单

适用范围：`memos-cloud-openclaw-plugin`

目的：把一组更接近真实用户提问方式的查询，整理成可人工逐条执行的回归验证材料，用来检查 Recall 检索、过滤和结果注入是否符合预期。

使用方式：
1. 先准备一组可控记忆样本，内容至少覆盖“偏好 / 决策 / 事实 / 故障 / 工具记忆 / 负样本”六类。
2. 打开插件 Recall 日志或 trace 输出，确保能看到请求 payload、召回结果数量、最终注入内容。
3. 按本清单逐条执行；每条只验证一个主要目标，避免同时改多个变量。
4. 每执行完一条，记录“是否命中 / 是否误召回 / 是否注入过长 / 是否有跨会话泄漏”。

建议记录字段：状态（通过/失败）、实际命中记忆、误召回、备注。

## 执行前准备

- 推荐开启 `recallEnabled=true`
- 如需验证偏好记忆，确认 `includePreference=true`
- 如需验证工具记忆，确认 `includeToolMemory=true`
- 如需验证知识库过滤，准备至少 2 个不同 `knowledgebaseIds`
- 如需验证会话隔离，分别准备 A/B 两个 session
- 如需验证全局召回差异，分别测试 `recallGlobal=true` 与 `recallGlobal=false`

## 人工执行检查项

每条查询建议按以下 6 项检查：

- 是否发出了 `/search/memory` 请求
- 请求参数是否符合预期（如 `user_id`、`session_id`、`readable_cube_ids`、`include_preference`、`search_tool_memory`、`relativity`）
- 返回结果数量是否合理，是否存在明显误召回
- 高风险约束类查询是否稳定排在前面
- 负样本和噪声查询是否被正确抑制
- 最终注入上下文是否可读、不过长、无跨会话泄漏

## 建议判定标准

- 通过：命中符合预期，且无明显误召回或泄漏
- 可接受：主结果正确，但有少量可容忍噪声
- 失败：未命中主结果、误召回明显、跨会话串数据，或高风险约束未被优先召回
